# examples/

Real outputs produced by `opentrust` on the simulated network in `network/`
(40 projects, 320 signed records, 50 incoming pull requests).

Everything here was generated by running the committed code — nothing is hand-written.
Reproduce with:

```bash
python tools/gen_network.py --out network
opentrust score     --manifest network/manifest.json --subject "github:@new-dev" --viewer proj-a
opentrust campaigns --incoming network/incoming
python tools/evaluate.py --network network
```

| File | What it shows |
| --- | --- |
| `score-new-dev.txt` | **The problem statement's case.** `@new-dev` is `TRUSTED` from `proj-a`'s viewpoint because `proj-b`, which `proj-a` trusts, vouched for them. `proj-x`'s denouncement is listed as ignored, with the reason. |
| `score-new-dev-as-seen-by-proj-x.txt` | The same contributor, the same records, a **different verdict** (`QUARANTINED`) from the viewpoint of `proj-x`, which trusts itself. This is what decentralisation means concretely: no global answer, only per-project answers. |
| `score-slop-account.txt` | A coordinated spammer denounced by three independently trusted projects → `QUARANTINED`, with the corroboration multiplier shown per record. |
| `campaign-alert.txt` / `.json` | The campaign: 30 accounts, 30 projects, 107 minutes, mean payload similarity 1.00, 5 of 6 independent signals fired, with example near-identical PR pairs and the affected project list. |
| `evaluation.txt` | Headline numbers: campaign recall 100% on identical payloads, 0 false positives on 12 legitimate PRs, 0 of 12 legitimate newcomers quarantined, runtime 0.32 s. |
| `evaluation-tier2.txt` | Same run with the local embedding model on: all 8 reworded campaign PRs are caught (0 / 8 without it), still 0 false positives. The campaign comes out as 38 accounts across 38 projects. |
| `trust-graph.dot` | The trust graph as Graphviz DOT, edge labels = declared weights. `dot -Tsvg trust-graph.dot -o trust-graph.svg` for the demo slide. |
| `network-summary.txt` | Signature verification over the whole network: 320 records accepted, 0 rejected. |

## The two-tier similarity story

`network/` contains two kinds of campaign payload:

- **30 identical payloads** — caught by Tier 1 (MinHash shingles). See `campaign-alert.json`.
- **8 paraphrased payloads** — the same intent, individually reworded. Tier 1 is blind to
  these by construction; they are recovered only by Tier 2 (local `qwen3-embedding:0.6b`
  embeddings via Ollama). With no model server running, `opentrust` reports Tier 1 only
  and says so, instead of failing.

Run `opentrust campaigns --incoming network/incoming --tier2` with Ollama up to see the
second tier's contribution.
